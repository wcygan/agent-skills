# 3D playbooks — explicit request only

Do not load this branch merely because a system has layers. Default technical
visuals to 2D. When 3D is requested, preserve the same semantic model and themes.

## Static isometric figure

Use a stable projection with one readable camera. Choose what depth means and state
it. Store coordinates in world space; derive ports and routes there; project nodes,
connectors, and labels through the same camera. Draw far surfaces before near ones.
Use modest depth and simple faces, with no decorative lighting or textures.

Good: two named regions on separate planes, clear service ownership, labeled
replication direction, horizontal text.
Bad: dramatic perspective, tall unlabeled blocks, hidden arrows, skewed tiny text.
Repair: reduce depth and perspective, separate groups, and move labels into readable
screen-space annotations. A flat legend must not be the only source of meaning.

For a small scene, projected SVG is sufficient and supports crisp export. Use a 3D
renderer only when scene complexity, occlusion, or the required interactions justify
it. No renderer makes an unverified domain model correct.

## Orbitable explanation

Provide a readable initial view, reset, bounded orbit/zoom, and keyboard/button
alternatives to dragging. Keep essential labels horizontal and associated with their
nodes. In supported camera positions, verify node attachment, occlusion, label
collisions, and route visibility. Avoid unrestricted orbit when the renderer cannot
correctly handle every angle. State the supported camera range.

Keep model state independent from camera and theme. Retain scene elements or update
only changed geometry where useful; avoid rebuilding a large unchanged scene on
every animation tick. A small reference may redraw on user input without needing an
animation engine. No automatic motion is required to demonstrate 3D.

## Spatial sequence or simulation

Use the same state-transition rules as the 2D playbooks. Camera movement is not a
state transition. Provide discrete step and reset controls; if autoplay is added,
respect reduced motion and visibility, and preserve the user's pause choice.

Static export uses the selected camera and model state, includes a meaningful caption,
and needs no interaction to explain the relationship. A still may omit temporal
behavior; link the interactive source for that behavior without claiming the still
proves it.

## Acceptance

Exercise each exposed camera control and its bounds, reset, keyboard access, themes,
and export. Inspect both default and extreme supported views. Check depth ordering
and visible endpoints. If correct occlusion cannot be achieved, simplify the scene,
restrict the camera honestly, or report the limitation; do not deliver hidden or
misattached relationships as a finished illustration.
