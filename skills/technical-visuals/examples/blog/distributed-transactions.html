DISTRIBUTED SYSTEMS / ATOMIC COMMIT

One transaction.
One shared outcome.

Prepare makes a promise. A durable decision resolves it. Follow both phases, then look inside a replicated participant.

PHASE ONE · PREPARE

YES means prepared, with locks held.

The coordinator asks each participant to validate and durably prepare its local change.

↔ Scroll the diagram to see both participants

This phase ends with votes ready to send. A prepared participant cannot safely abort just because it times out.

PHASE TWO · DECIDE

Record the decision before sending it.

Try all four vote combinations. Any NO produces ABORT; two YES votes permit COMMIT.

↔ Scroll the diagram to see both participants

A NO voter has already rolled back and unlocked. A YES voter waits until it learns the durable decision. Missing votes can cause an abort only before COMMIT has been recorded.

TWO DISTINCT COORDINATION BOUNDARIES

Quorum within each shard. Every vote across shards.

Each leader first replicates PREPARE to its own consensus group. The coordinator then needs one YES from each shard.

↔ Scroll the diagram to see both shard groups

Simplified leader/quorum trace: each group contains three replicas and needs two durable copies. The third replica may catch up later. This is not a global four-of-six vote, nor a single protocol shared by all distributed SQL databases.
