Kafka partitioning

The same key chooses the same partition

Scroll the diagram horizontally to follow the logs.

Speed

With key routing and a fixed partition count, the same key selects the same log. Each partition has its own offsets. Changing the slider restarts this sample; Kafka keeps existing records in their original partitions.

Keys are bytes

Kafka Java-compatible Murmur2 hashes the UTF-8 key. Clear the sign bit, then take the remainder: (hash & 0x7fffffff) % N. Repeated keys choose the same log for a fixed N.

Offsets are local

Each partition starts at offset 0. Record IDs show producer order; offsets show order within one log. There is no single topic-wide offset.

Changing N changes routing

Changing the partition count here restarts the sample under the new rule. In Kafka, existing records stay in their original logs; later records with the same key may route elsewhere.

This is a routing illustration. Explicit round-robin is a comparison strategy, not a claim about Kafka’s default unkeyed producer behavior. Log slots show this sample, not a capacity limit.
