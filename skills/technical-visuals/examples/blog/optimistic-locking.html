Optimistic locking

A stale version cannot change the row

Each update checks the version it read. A stale attempt changes zero rows; rereading lets the worker retry with the current version.

SQL and transaction details 
UPDATE inventory_items
SET available = available - 1,
    version = version + 1
WHERE sku = 'SKU-42'
  AND available > 0
  AND version = :read_version;

The SKU is unique. Reads and writes use separate short transactions. No lock spans the worker’s checkout; each guarded write still takes an ordinary row lock. A commits before B submits its stale write. A zero affected-row count can also mean no stock or a missing row. The worker rereads and recomputes before retrying.
