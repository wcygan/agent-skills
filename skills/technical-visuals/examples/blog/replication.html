Receiving is not the same as applying

Scroll the diagram horizontally to see the full pipeline →

Illustrative ticks, not measured MySQL latency. All six writes update one existing record. Group ordering and successful certification are combined; “received” means admission to a local application queue. A healthy majority remains available. Brief outages assume missed messages remain in cache; removal after 10 illustrative ticks requires rejoin and donor recovery. Stronger consistency settings may wait for synchronization.

A replica can buffer several writes while applying one at a time. Reads show the last applied value, so a replica can have received a write without showing it yet.
