01 Latest team events

A team member wants the latest 50 updates, newest first.

Team 42 · ActivityProduct view
Newest first · 50 results
10:42Maya uploaded a file
10:38Leo joined the team
10:31Ana posted an update

Illustrative screen · sample records

How it works API · SQL · design choices

Database workload: WHERE tenant_id = 42; ORDER BY created_at DESC, event_id DESC; LIMIT 50.

1 · API request
GET /teams/42/events

Path parameters:
  tenant_id: 42

Query parameters:
  limit: 50
2 · Use lookup path

Index: (tenant_id, created_at DESC, event_id DESC).

3 · SQL on the logical table
Illustrative SQL
SELECT
  * 
FROM events 
WHERE tenant_id = 42 
ORDER BY
  created_at DESC,
  event_id DESC 
LIMIT 50;
MySQL index · Composite secondary B-tree
CREATE INDEX events_feed
ON events (
  tenant_id,
  created_at DESC,
  event_id DESC
);

InnoDB secondary entries carry the clustered primary key. Assume a separate primary key exists; measure table reads and write overhead.

Tenant equality narrows the index; the remaining keys supply order.

Write / tradeoff: Each event insert maintains the composite index; event ID breaks timestamp ties.

How it works API · SQL · design choices

Database workload: Find one account by normalized email; new accounts must not reuse that email.

1 · API request
POST /sessions

Body:
{
  "email": "alice@example.com"
}
2 · Use lookup path

Index: UNIQUE(email_normalized); normalize the API value before lookup.

3 · SQL on the logical table
Illustrative SQL
SELECT
  account_id,
  password_hash 
FROM accounts 
WHERE email_normalized = 'alice@example.com';
MySQL index · Unique secondary B-tree
CREATE UNIQUE INDEX accounts_email
ON accounts (
  email_normalized
);

InnoDB secondary entries carry the clustered primary key. Assume a separate primary key exists; measure table reads and write overhead.

Account lookup is one step of sign-in; the service must still verify credentials.

Write / tradeoff: Normalize emails under an explicit identity policy. A unique index enforces that stored key’s uniqueness.

A customer filters order history to paid orders, newest first.

Customer 12 · OrdersProduct view
Status: Paid · Newest first

#1037Keyboard · Paid

Illustrative screen · sample records

How it works API · SQL · design choices

Database workload: WHERE customer_id = 12 AND status = paid; ORDER BY created_at DESC; LIMIT 20.

1 · API request
GET /customers/12/orders

Path parameters:
  customer_id: 12

Query parameters:
  status: paid
  limit: 20
2 · Use lookup path

Index: (customer_id, status, created_at DESC).

3 · SQL on the logical table
Illustrative SQL
SELECT
  * 
FROM orders 
WHERE customer_id = 12
  AND status = 'paid' 
ORDER BY
  created_at DESC 
LIMIT 20;
MySQL index · Composite secondary B-tree
CREATE INDEX orders_customer_status
ON orders (
  customer_id,
  status,
  created_at DESC,
  order_id DESC
);

InnoDB secondary entries carry the clustered primary key. Assume a separate primary key exists; measure table reads and write overhead.

The two equality filters precede the ordering key. Add order_id for deterministic pagination.

Write / tradeoff: Choose equality columns before ordering. Index maintenance adds write cost; validate with EXPLAIN on realistic distributions.

05 Text document search

A reader searches for documents about cats.

Document searchProduct view
Search: cat
Doc 1Caring for your cat
Doc 3Cat nutrition basics

Illustrative screen · sample records

How it works API · SQL · design choices

Database workload: Find documents containing a word anywhere in their text; updates change document contents.

1 · API request
GET /documents

Query parameters:
  q: cat
2 · Use lookup path

Index: FULLTEXT(body); choose token matching semantics.

3 · SQL on the logical table
Illustrative SQL
SELECT
  document_id 
FROM documents 
WHERE MATCH(body) AGAINST ('cat' IN NATURAL LANGUAGE MODE);
MySQL index · FULLTEXT inverted index
CREATE FULLTEXT INDEX documents_body
ON documents (
  body
);

Use MATCH … AGAINST. Tokenization, stopwords, and minimum token size define what matches.

Unlike LIKE '%cat%', this searches parsed tokens; stopwords and token lengths affect matches.

Write / tradeoff: Maintain tokens when text changes. Full-text token matching differs from arbitrary substring matching; choose semantics deliberately. Full-text reference

Implementation notes

For MySQL 8.0+ / InnoDB, use a B-tree on (tenant_id, created_at DESC, event_id DESC). Tenant equality narrows the range; event ID breaks timestamp ties. Payload may require table reads. Verify with EXPLAIN and representative read/write measurements.

Illustrative workload; measure on your own data. Official reference
