SYSTEM DESIGN / INTERVIEW CHEATSHEET

One step at a time.

Five steps. One example: a URL shortener.

THE BASIC GUIDELINE

Start simple. Fix the bottleneck.

Make one request work end to end.
Find what limits it → add a fix → explain the cost.

01

Clarify

0–5 min

Agree on what to build.

URL SHORTENER EXAMPLE

Define scope

“Create and open short links. Agree on redirect latency and whether new links must be readable immediately. Analytics can wait.”

02

Estimate

5–8 min

Calculate only what changes a decision.

URL SHORTENER EXAMPLE

Estimate traffic

“Assume one million opens a day and 10× peaks. Compare the peak to measured service capacity before adding infrastructure.”

03

Sketch

8–18 min

Draw the path. Define the data.

URL SHORTENER EXAMPLE

Map data

POST /links saves code → target before acknowledging. GET /{code} looks it up and returns a redirect.

04

Deep dive

18–35 min

Solve one bottleneck. Explain the cost.

URL SHORTENER EXAMPLE

Add cache

“If repeated reads exceed the latency or capacity target, cache popular links. Updates may stay stale until expiry or invalidation.”

05

Stress-test

35–45 min

Check load, failures, and recovery.

URL SHORTENER EXAMPLE

Plan recovery

“Trace the user-visible result, then the recovery path. Check that surviving capacity can handle failover.”

Try a failure

Cache down: Can the database handle fallback traffic? What work must be limited?

Database down: Which reads can use cached data? Which writes fail or wait?

Saved, response lost: The client cannot know whether the write succeeded. What idempotency key or duplicate policy makes a retry safe?

Practice with a problem

Choose a problem in the sidebar. Spend five minutes clarifying scope, then sketch one working request. Use the skill for guided practice and feedback.

Before you finish

Access: Who may read or change each object?

Signals: How will you measure success, latency, errors, and saturation?

Recovery: How much data loss and downtime are acceptable? How will you test a restore?
