# Companion contracts

The parent owns the reader questions, shared component/scenario model, view
selection, cross-view consistency, and final explanation. Pass bounded scope,
revision, relevant model entries, existing evidence, remaining question, and
phase authority to each specialist. Reuse adequate artifacts.

Tracing is analytical. Visual delivery permits the requested task-owned
artifact, not application changes. Carry the entrypoint's route and fallback
policy into handoffs; inconclusive results return supported evidence and the
exact gap. The visual style is required even when presentation must be performed
directly without an available companion.

## `trace-codepath`: scenario execution

- **When:** One selected journey has unresolved entry, dispatch, branch, or
  boundary semantics.
- **Input:** Trigger, entry anchor, selected variant, terminal sink, known
  components, and the uncertain segment.
- **Output:** Evidence-backed path, edge ledger, selected implementations,
  conditions, effects, and opaque or uncertain boundaries.
- **Complete when:** The relevant entry-to-sink path is established or the
  exact unresolved edge is identified.
- **Parent use:** Reconcile the path into overview and journey views; preserve
  distinctions between possible source relationships and observed execution.

## `trace-data-lineage`: identity and authoritative state

- **When:** A material record, field, event, copy, or derived result has
  uncertain provenance, meaning, transformation, ownership, or consumers.
- **Input:** Selected data unit, identity rule, origin/sink, variant, known
  path, and precise lineage question.
- **Output:** Lineage edges, transformations, authoritative and derived
  owners, relevant lifecycle semantics, evidence, and unknown mappings.
- **Complete when:** The necessary origin-to-consumer relationships are
  supported or an exact missing mapping/owner is named.
- **Parent use:** Join data edges to the same components and journey IDs; a
  matching field name alone does not establish shared identity.

## `map-production-scenario`: integrated operational journey

- **When:** A selected operation requires execution, data, and signal lenses
  together to answer the reader's question.
- **Input:** One scenario/variant, terminal outcome, shared component IDs,
  environment and evidence constraints, and bounded question.
- **Output:** Reconciled execution, lineage, signal coverage, and applicable
  failure overlay, with shared identities and limitations.
- **Complete when:** The operation has a supported combined account or its
  missing evidence is explicit.
- **Parent use:** Reuse this dossier's constituent lenses; translate its
  identities into the system map without launching duplicate traces.

## `style-technical-visuals`: core presentation

- **When:** Building the system explanation's visual artifact; this is a core
  phase rather than optional final polish.
- **Input:** Reconciled model, teaching questions, requested format, audience,
  viewports/themes, project tokens if present, evidence labels, and explicitly
  selected 2D dimension unless the user requested otherwise.
- **Output:** Styled visual using the selected branch and closest active
  example, stable semantic colors, consistent design tokens, labeled role or
  verified technology icons, correct geometry, and presentation-check results.
- **Complete when:** Supported views and controls are checked, the visual
  answers the questions without color/motion dependence, and limitations are
  explicit. The parent validates factual meaning against its ledger.
- **Parent use:** Keep the style skill as presentation authority. Its examples
  supply patterns, not evidence about the target system. The supplied dimension
  settles its dimension-selection prerequisite.

## `domain-modeling`: only an authorized model change

- **When:** The user also requested clarification that changes domain concepts,
  glossary entries, or durable decisions; ordinary vocabulary consultation stays
  in parent analysis.
- **Input:** Current terminology, supported code/document conflicts, proposed
  meanings, scenarios, and explicit documentation/model scope.
- **Output:** Authorized model/document changes, resolved terminology, and
  outstanding decisions.
- **Complete when:** Requested concepts are resolved and in-scope documents
  updated, or the consequential ambiguity is identified.
- **Parent use:** Incorporate resolved meanings into all affected views. Keep
  this branch outside a read-only orientation request.
