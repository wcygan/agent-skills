# Feature

Build new or changed user behavior.

1. Define observable acceptance criteria and investigate the existing integration points.
2. Use [design](../../wcygan-design/SKILL.md) when ownership or structure is unsettled.
   Name the data shape and who controls each state transition before implementation.
3. Follow [implement](../../wcygan-implement/SKILL.md). Resolve blocking dependencies
   first; split work only where outputs and write ownership can be separated.
4. Follow [verify](../../wcygan-verify/SKILL.md) against the real affected surface.
   Use [review](../../wcygan-review/SKILL.md) for consequential or contested choices.

Complete with the implemented outcome, design tradeoffs, evidence, and open issues.
Use [deliver](../../wcygan-deliver/SKILL.md) only to the requested destination.
