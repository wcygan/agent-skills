# Ambitious outcome

Choose, enable, or pursue a valuable outcome at the requested level of ownership.

1. If the outcome is undecided, use
   `discover-ambitious-goals`. A request for
   ideas ends with ranked opportunities; leave the choice of a new product
   direction to the user, because product direction is their decision. Continue
   when the objective is already selected or delegated.
2. If inputs, execution, verification, or authority are uncertain, use
   `prepare-agent-objective`. Reuse an
   existing tested contract. Preparation-only work ends with readiness and gaps.
3. For a bounded improvement, follow the matching feature, bug-fix, or experiment
   playbook. For a stretch target, use
   `wcygan-experiment` with a fixed acceptance contract.
4. For sustained outcomes, use `maintain-outcome`
   for a bounded cycle and checkpoint. Future runs need a working trigger the
   user approved; record its actual status and stop mechanism.
5. Compare results with required and stretch targets separately. Report observed
   scope, evidence, operational confirmation still pending, and the next useful move.

Complete at the requested boundary: opportunities, tested readiness, a verified
improvement, or an evidenced maintenance cycle. A go-ahead given in one phase
still holds in the next. An ambitious goal brings no budget and no go-ahead to
publish with it; get each explicitly.
