# Technical explanation

Explain a system, behavior, or change through a concise visual artifact.

1. Identify the reader's question and authoritative facts. Use
   [investigate](../../wcygan-investigate/SKILL.md) when behavior is uncertain;
   do not invent relationships to complete a drawing.
2. Use [technical-visuals](../../technical-visuals/SKILL.md) to choose the input
   contract, design system, format, and matching example. Default to 2D and use
   3D only when explicitly requested. Keep a small static figure small.
3. Verify both meaning and rendered presentation, including controls or export
   when present. Use [write-clearly](../../write-clearly/SKILL.md) for labels
   and the short caption; preserve qualifications and evidence.
4. Deliver the requested artifact. For a PR, incorporate it through
   [prepare-pull-request](../../prepare-pull-request/SKILL.md) and retain the
   current authorization and publication checkpoint.

Complete with the editable artifact, requested preview, source/evidence context,
and any unverified behavior. A conceptual visual does not prove runtime behavior.
