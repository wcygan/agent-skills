One search can become two

A secondary index finds the primary key, which identifies the row. MySQL uses that key to find the full row in the primary index.

Two index searches do not always cause two disk reads. MySQL may already have the pages in memory.

See a range scan move sideways

A range scan finds a block of ordered values. MySQL jumps to the first match, moves through linked leaf pages, then stops at the upper limit.

Range query · INDEX(city, id) SELECT city, id FROM users WHERE city >= 'Chicago' AND city < 'Detroit' ORDER BY city, id;

Faster reads add write work

Useful indexes can shorten reads. MySQL must also update those indexes when affected data changes.

Remember these four ideas

CompareOrdered values let MySQL skip most pages and records.
Use the keyA secondary index can send a primary key to the primary index.
Stop after one indexA covering index already has every value the query needs.
Move through leavesA range scan follows links until a value reaches the upper limit.
