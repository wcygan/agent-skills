# Record

Read the shared [principle index](../wcygan-mode/references/principles.md) at entry and reconsider it as the work changes. Report each principle that changed a decision, with the specific choice it shaped.

Read linked components only when their stated condition applies, so the context
stays small. Keep the task's scope and any checkpoint the user set.

1. Choose the requested output. Use `decision-log` for an ongoing audit trail,
   `recover-context` for pickup, or `progress-report` for a concise status update.
2. For a requested retrospective, use `improve-workflow`. Apply `prevent-recurrence`
   when structural fixes to repeated mistakes are also in scope.
3. When asked to capture lasting personal preferences, use `personalize-workflow`.
   Write a permanent rule only from a preference the user stated or showed
   repeatedly, because a rule made from one task's notes would shape every
   future task.
4. Check that evidence pointers resolve, uncertainty survives summarization, and
   unfinished work has enough context for its next owner. Use `write-clearly`
   when the prose needs refinement.

Done when the requested record is useful, accurate, and stored or presented in its
intended scope. Run only the relevant branch; an update needs no retrospective.
